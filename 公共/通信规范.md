# 角色间通信规范

> 原则：**状态走 GitHub Issue，产出走文件，沟通走 Issue 评论**

> 本文件是通信协议的唯一权威来源。

## GitHub Issue

所有角色通过 `gh` CLI 操作 GitHub Issue。不需要额外配置 MCP 或第三方工具。

### Label 体系

| Label | 用途 | 颜色建议 |
|-------|------|----------|
| `task` | 任务/需求 | 蓝色 |
| `bug` | 缺陷 | 红色 |
| `question` | 角色间提问 | 黄色 |
| `review` | 代码审查 | 紫色 |
| `P0` `P1` `P2` `P3` | 优先级 | — |
| `待拆解` `待设计` `设计中` `待开发` `开发中` `待审查` `待测试` `已完成` `已阻塞` | 状态 | — |
| `架构师` `UI设计员` `后端开发` `前端开发` `审查员` `测试人员` `运维` | 负责角色 | — |

## 常用操作

### 创建任务

```bash
gh issue create --title "L1 TASK-001: 任务标题" --body "需求描述..." --label "task,P1,待设计,架构师"
```

### 查看自己的任务

```bash
# 架构师查看待设计任务
gh issue list --label "task,待设计,架构师"

# 后端开发查看待开发任务
gh issue list --label "task,待开发,后端开发"
```

### 更新状态（改 Label）

```bash
# 从"待设计"改为"待开发"
gh issue edit 1 --remove-label "待设计" --add-label "待开发"
```

### 角色间沟通（Issue 评论）

```bash
# 在任务 Issue 下提问
gh issue comment 1 --body "@架构师 这个接口的返回格式需要确认"

# 单独创建提问 Issue
gh issue create --title "Q: 关于用户认证的技术选型" --body "问题内容..." --label "question,架构师"
```

### 报告 Bug

```bash
gh issue create --title "BUG: 登录接口返回 500" --body "复现步骤：..." --label "bug,P1,后端开发"
```

### 提交审查

```bash
gh issue create --title "L3 REVIEW: L2 TASK-001 代码审查" --body "审查意见..." --label "review" --assignee ""
# 或在任务 Issue 下评论审查结果
gh issue comment 1 --body "## 审查结果：通过\n审查意见..."
```

### 关闭任务

```bash
gh issue close 1 --comment "已完成，代码已合并"
```

## 每个角色的操作速查

| 角色 | 核心操作 |
|------|----------|
| PM | `gh issue create`（创建任务）、`gh issue list --label bug`（跟踪 Bug） |
| 架构师 | `gh issue list --label "待设计,架构师"`、`gh issue edit --add-label 待开发` |
| UI设计员 | `gh issue list --label "待设计,UI设计员"`、`gh issue edit` |
| 后端开发 | `gh issue list --label "待开发,后端开发"`、`gh issue edit --add-label 待审查` |
| 前端开发 | `gh issue list --label "待开发,前端开发"`、`gh issue edit --add-label 待审查` |
| 审查员 | `gh issue list --label 待审查`、`gh issue comment`（审查意见） |
| 测试人员 | `gh issue list --label 待测试`、`gh issue create --label bug`（报 Bug） |
| 运维 | `gh issue list --label 运维`、`gh issue comment` |
