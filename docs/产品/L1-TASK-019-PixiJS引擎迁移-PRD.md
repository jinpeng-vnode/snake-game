# L1-TASK-019 PixiJS 引擎迁移 产品需求文档（PRD）

## 1. 项目概述

### 1.1 项目背景
贪吃蛇项目 v2.0.0 在上一轮引擎重构中选用了 Kaplay（原 Kaboom.js）引擎，替代了原生 Canvas API。重构后代码结构为 TypeScript + Vite + Kaplay，包含 `src/` 下 13 个模块文件（scenes/、objects/、systems/）。

用户反馈 Kaplay 引擎选型不当，需要替换为 **PixiJS** 引擎。原因包括：
- Kaplay 社区规模较小（4k⭐），长期维护存在风险
- PixiJS 社区活跃（44k⭐），生态成熟，文档完善
- PixiJS 作为专业 2D 渲染引擎，渲染性能更优

### 1.2 项目目标
- 将游戏引擎从 Kaplay 替换为 PixiJS，移除 Kaplay 依赖
- 100% 保留现有全部功能和用户体验，用户无感知切换
- 保持现有项目结构（TypeScript + Vite），最小化变更范围
- 部署方式不变（GitHub Pages 静态部署）

### 1.3 目标用户
- 手机用户：通过手机浏览器访问游戏的休闲玩家
- PC 用户：使用键盘操控的玩家

### 1.4 使用场景
1. 通勤/碎片时间：用户在手机浏览器打开游戏，用触屏滑动或虚拟方向键操控
2. PC 休闲：用户用键盘（方向键或 WASD）操控，享受音效和粒子特效
3. 安静环境：用户一键静音，关闭所有音效

## 4. 用户流程

### 4.1 核心流程

#### 4.1.1 开始游戏流程
1. 用户打开 index.html
2. PixiJS 引擎初始化，页面自适应屏幕尺寸
3. 画布显示游戏标题和"开始游戏"提示
4. 屏幕宽度 < 768px 时，画布下方显示虚拟方向键
5. 用户点击画布/按空格/按任意方向键
6. 游戏开始，蛇从画布中央出现，初始长度 3 格，方向向右
7. 蛇以 180ms/tick 速度自动移动
8. 食物随机出现在空白网格上

**判断分支：**
- 如果用户之前设置过静音 → 读取 localStorage，保持静音状态
- 如果屏幕宽度 < 768px → 显示虚拟方向键
- 如果屏幕宽度 ≥ 768px → 隐藏虚拟方向键

#### 4.1.2 吃食物流程
1. 蛇头移动到食物所在网格
2. 系统判断食物类型
3. 播放吃食物音效
4. 触发吃食物粒子特效（食物颜色）
5. 根据食物类型执行效果：
   - 普通：蛇身 +1，分数 +10
   - 加速：蛇身 +1，分数 +15，触发加速效果 5 秒（tick ×0.7）
   - 减速：蛇身 +1，分数 +15，触发减速效果 5 秒（tick ×1.3）
   - 双倍：蛇身 +1，分数 +20（后续得分 ×2 持续 8 秒）
   - 缩短：蛇身缩短，分数 +5
6. 分数乘以当前得分倍率
7. 更新分数显示，如超过最高分则更新最高分
8. 新食物按概率随机生成

**异常流程：**
- 画布已满（蛇占满所有格子）→ 触发通关状态

#### 4.1.3 特殊食物限时流程
1. 特殊食物生成，开始倒计时（6-8 秒）
2. 剩余 ≤ 3 秒时，食物以 300ms 周期闪烁
3. 倒计时归零 → 食物消失，重新生成新食物

#### 4.1.4 游戏结束流程
1. 蛇头碰到墙壁或自身
2. 游戏状态切换为 gameOver
3. 播放游戏结束音效
4. 触发游戏结束粒子特效
5. 画布显示半透明遮罩 + "游戏结束" + 最终分数
6. 如果分数 > 最高分，更新 localStorage
7. 用户点击画布/按空格 → 重新开始

#### 4.1.5 暂停与恢复流程
1. 游戏进行中，用户按 ESC 或 P
2. 游戏状态切换为 paused，游戏循环停止
3. 画布显示半透明遮罩 + "已暂停"
4. 用户按 ESC/P/空格 → 恢复游戏，遮罩消失，循环继续

## 6. 非功能需求

- 性能：迁移后游戏帧率 ≥ 30fps，tick 间隔精度与 Kaplay 版本一致
- 兼容性：Chrome/Safari/Firefox 最新版，iOS Safari、Android Chrome
- 响应式：最小支持宽度 320px（iPhone SE），最大 1000px
- 包体积：PixiJS 引入后总资源大小应控制在合理范围，不影响 GitHub Pages 加载速度
- 部署：纯静态文件，`index.html` 为入口，GitHub Pages 直接部署
- 视觉一致性：迁移后的游戏画面、颜色、布局必须与 Kaplay 版本视觉一致

## 7. 迁移约束（架构师必读）

### 7.1 技术约束
- 引擎从 Kaplay 替换为 PixiJS，移除 `kaplay` npm 依赖
- 构建工具保持 Vite + TypeScript 不变
- 最终产物为纯静态文件，可部署到 GitHub Pages
- 现有游戏参数（`src/constants.ts` 中的所有常量）必须保留，数值不变
- 音效系统仍使用 Web Audio API 合成（不引入音频文件）
- 类型定义（`src/types.ts`）中的业务类型保持不变，仅替换引擎相关类型

### 7.2 迁移策略建议
- 保持现有 `src/` 目录结构（scenes/、objects/、systems/），替换内部引擎调用
- PixiJS 是纯渲染引擎，不内置场景管理、输入系统、粒子系统，架构师需设计补充方案
- 分数面板、静音按钮、虚拟方向键保留为 DOM 元素（与 Kaplay 版本一致）
- 建议分模块迁移，每个模块迁移后可独立验证

### 7.3 Kaplay → PixiJS 差异点（架构师需重点设计）

| 能力 | Kaplay 现有方案 | PixiJS 需要的方案 |
|------|----------------|------------------|
| 场景管理 | `k.scene()` + `k.go()` 内置 | 无内置，需自行设计场景管理 |
| 游戏循环 | `k.onUpdate()` 内置 | `app.ticker` 提供帧循环 |
| 键盘输入 | `k.onKeyPress()` 内置 | 无内置，需用原生 DOM 事件 |
| 触屏输入 | 需自行实现 | 需自行实现（与现有方案类似） |
| 粒子系统 | 内置粒子 | 需用 `@pixi/particle-emitter` 或手动实现 |
| 图形绘制 | `k.rect()` / `k.circle()` 组件 | `PIXI.Graphics` API |
| 文字渲染 | `k.text()` 组件 | `PIXI.Text` |
| 对象管理 | `k.add()` + 组件系统 | `container.addChild()` 显示列表 |

| 文件 | 职责 | 迁移影响 |
