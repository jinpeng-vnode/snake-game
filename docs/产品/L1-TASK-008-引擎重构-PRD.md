# L1-TASK-008 贪吃蛇游戏引擎重构 产品需求文档（PRD）

## 1. 项目概述

### 1.1 项目背景
当前贪吃蛇项目使用原生 Canvas API 手写渲染、输入处理、粒子系统、音效合成等模块，共 11 个 JS 文件约 1664 行代码。随着功能迭代（触屏适配、多种食物、特效系统、粒子特效等），代码复杂度持续上升，模块间耦合加深，维护和扩展成本越来越高。

核心痛点：
- `renderer.js`（395 行）和 `game.js`（390 行）承担了大量底层绘制和游戏循环逻辑，业务代码与渲染代码混杂
- 粒子系统、碰撞检测、动画循环等均为手写实现，缺乏引擎级别的抽象和优化
- 新增功能（如更复杂的特效、动画）需要不断扩展底层代码，开发效率低

### 1.2 项目目标
- 引入 Web 游戏引擎（具体选型由架构师决定，如 Phaser、PixiJS 等），替代手写的底层模块
- 用引擎能力重写现有全部功能，降低代码复杂度和维护成本
- 100% 保留现有功能和用户体验，用户无感知切换
- 部署方式不变（GitHub Pages 静态部署，纯前端无后端）

### 1.3 目标用户
- 手机用户：通过手机浏览器访问游戏的休闲玩家
- PC 用户：使用键盘操控的玩家

### 1.4 使用场景
1. 通勤/碎片时间：用户在手机浏览器打开游戏，用触屏滑动或虚拟方向键操控
2. PC 休闲：用户用键盘（方向键或 WASD）操控，享受音效和粒子特效
3. 安静环境：用户一键静音，关闭所有音效

## 4. 用户流程

### 4.1 核心流程

#### 4.1.1 开始游戏流程
1. 用户打开 index.html
2. 引擎初始化，页面自适应屏幕尺寸
3. 画布显示游戏标题和"开始游戏"提示
4. 屏幕宽度 < 768px 时，画布下方显示虚拟方向键
5. 用户点击画布/按空格/按任意方向键
6. 游戏开始，蛇从画布中央出现，初始长度 3 格，方向向右
7. 蛇以 180ms/tick 速度自动移动
8. 食物随机出现在空白网格上

**判断分支：**
- 如果用户之前设置过静音 → 读取 localStorage，保持静音状态
- 如果屏幕宽度 < 768px → 显示虚拟方向键
- 如果屏幕宽度 ≥ 768px → 隐藏虚拟方向键

#### 4.1.2 吃食物流程
1. 蛇头移动到食物所在网格
2. 系统判断食物类型
3. 播放吃食物音效
4. 触发吃食物粒子特效（食物颜色）
5. 根据食物类型执行效果：
   - 普通：蛇身 +1，分数 +10
   - 加速：蛇身 +1，分数 +15，触发加速效果 5 秒（tick ×0.7）
   - 减速：蛇身 +1，分数 +15，触发减速效果 5 秒（tick ×1.3）
   - 双倍：蛇身 +1，分数 +20（后续得分 ×2 持续 8 秒）
   - 缩短：蛇身缩短，分数 +5
6. 分数乘以当前得分倍率
7. 更新分数显示，如超过最高分则更新最高分
8. 新食物按概率随机生成

**异常流程：**
- 画布已满（蛇占满所有格子）→ 触发通关状态

#### 4.1.3 特殊食物限时流程
1. 特殊食物生成，开始倒计时（6-8 秒）
2. 剩余 ≤ 3 秒时，食物以 300ms 周期闪烁
3. 倒计时归零 → 食物消失，重新生成新食物

#### 4.1.4 游戏结束流程
1. 蛇头碰到墙壁或自身
2. 游戏状态切换为 gameOver
3. 播放游戏结束音效
4. 触发游戏结束粒子特效
5. 画布显示半透明遮罩 + "游戏结束" + 最终分数
6. 如果分数 > 最高分，更新 localStorage
7. 用户点击画布/按空格 → 重新开始

#### 4.1.5 暂停与恢复流程
1. 游戏进行中，用户按 ESC 或 P
2. 游戏状态切换为 paused，游戏循环停止
3. 画布显示半透明遮罩 + "已暂停"
4. 用户按 ESC/P/空格 → 恢复游戏，遮罩消失，循环继续

## 5. 数据需求

### 5.1 需要持久化的数据
| 数据项 | 说明 | 存储方式 |
|--------|------|----------|
| 最高分 | 历史最高分数 | localStorage，键名 `snakeHighScore` |
| 静音状态 | 是否静音 | localStorage，键名 `snakeMuted` |

### 5.2 数据展示规则
- 分数：实时更新，整数显示
- 最高分：页面加载时从 localStorage 读取，游戏中实时比较更新
- 特效剩余时间：毫秒精度内部计算，显示时取秒级

## 6. 非功能需求

- 性能：引擎重构后游戏帧率 ≥ 30fps，tick 间隔精度与原版一致
- 兼容性：Chrome/Safari/Firefox 最新版，iOS Safari、Android Chrome
- 响应式：最小支持宽度 320px（iPhone SE），最大 1000px
- 包体积：引擎引入后总资源大小应控制在合理范围，不影响 GitHub Pages 加载速度
- 部署：纯静态文件，`index.html` 为入口，GitHub Pages 直接部署
- 视觉一致性：重构后的游戏画面、颜色、布局必须与现有版本视觉一致
